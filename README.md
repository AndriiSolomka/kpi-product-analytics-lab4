# DataPilot — AI-асистент продуктового аналітика

Лабораторна робота №4, курс «Методи та засоби продуктової аналітики».
Соломка Андрій, група ІМ-31.

DataPilot — це CLI-інструмент, який забирає на себе рутинну частину роботи
аналітика: профілювання нового датасету, пошук сегментів, що поводяться
інакше, відповіді на разові питання по даних і підготовку тексту для
стейкхолдера. Усі числа рахує pandas, а LLM відповідає лише за інтерпретацію
та формулювання. Кожне число, яке модель назвала у своїй відповіді,
автоматично звіряється з фактами — те, чого в даних немає, позначається як
непідтверджене прямо у виводі.

## Реалізовані функції

| Команда | Що робить | Пункт завдання |
|---|---|---|
| `eda` | Профілює CSV: типи, пропуски, викиди за IQR, дублікати, прапорці якості даних; LLM пише інтерпретацію | 1 |
| `hypotheses` | Рахує зрізи по сегментах, кореляції та денні аномалії, LLM формулює 5–10 перевірюваних гіпотез із числами | 2 |
| `ask` | Питання природною мовою → код pandas → виконання в пісочниці → результат; код завжди показується | 3 |
| `explain` | Декомпозиція зміни метрики між двома періодами по сегментах + гіпотеза причини | 4 |
| `summary` | Executive summary для керівника з JSON-метрик | 5 |

Додатково (пункт 6): **верифікатор чисел** `datapilot/verify.py` — витягує всі
числа з відповіді моделі та звіряє їх із фактами з допуском 2%, враховуючи
округлення й перерахунок у тисячі та відсотки.

## Швидкий старт

```bash
git clone https://github.com/AndriiSolomka/kpi-product-analytics-lab4.git
cd kpi-product-analytics-lab4
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env     # і вписати свій ключ
python -m datapilot eda data/daily_metrics.csv
```

### Де взяти API-ключ

* **Anthropic** (за замовчуванням): console.anthropic.com → API keys → Create key.
  Покласти в `.env` як `ANTHROPIC_API_KEY=sk-ant-...`
* **OpenAI**: platform.openai.com → API keys. У `.env` додати
  `OPENAI_API_KEY=sk-...` і `DATAPILOT_PROVIDER=openai`.

Провайдер визначається автоматично за наявним ключем; модель можна змінити
змінною `DATAPILOT_MODEL`.

**Без ключа інструмент теж запускається.** Прапорець `--no-llm` виконує лише
детерміновану частину (усі розрахунки й таблиці), а без ключа і без прапорця
вмикається режим `mock` із заглушками — зручно для тестів і CI.

### 3. Питання природною мовою

```bash
python -m datapilot ask data/payments.csv "Покажи топ-10 країн за виручкою"
```

Інструмент показує згенерований код, пояснення, припущення — і лише потім
результат, щоб аналітик міг перевірити логіку, а не довіряти чорній скриньці.

### 4. Гіпотези та executive summary

```bash
python -m datapilot hypotheses data/users.csv --json demo/hypotheses.json
python -m datapilot summary demo/metrics.json --audience "CEO"
```

Якщо модель назве число, якого немає у фактах, воно буде позначене:

```
⚠ Перевірка чисел: 1 з 14 не знайдено у фактах → [4.1]
  Ці значення модель, найімовірніше, вигадала — не вставляйте їх у звіт.
```

## Демонстраційні дані

У `data/` лежить зріз навчальної бази мобільного застосунку за
2024-04-05 – 2024-05-11 (той самий продукт, що й у лабораторній №3):

| Файл | Рядків | Що містить |
|---|---|---|
| `users.csv` | 60 000 | користувач: реєстрація, платформа, країна, стать, вік, A/B-група, сесії, активність, виручка |
| `daily_metrics.csv` | 7 825 | день × платформа × країна: нові користувачі, DAU, сесії, хвилини, активності, платники, виручка |
| `payments.csv` | 11 330 | окремі платежі з типом фічі, платформою і країною |

Дані містять реальну аномалію — реєстрації на iOS зупиняються після 20 квітня,
— на якій зручно показувати роботу команди `explain`.

## Як це влаштовано

```
datapilot/
  llm.py          шар доступу до LLM: Anthropic / OpenAI / mock, парсинг JSON
  profiling.py    детерміноване профілювання, прапорці якості даних
  insights.py     зрізи по сегментах, кореляції, денні аномалії за z-score
  eda.py          функція 1
  hypotheses.py   функція 2
  nl2pandas.py    функція 3 + пісочниця для згенерованого коду
  anomaly.py      функція 4 (декомпозиція внесків сегментів)
  summary.py      функція 5
  verify.py       звірка чисел з відповіді моделі з фактами
  cli.py          інтерфейс командного рядка
```

Принцип усюди однаковий: **код рахує → модель пояснює → код перевіряє**.
Модель ніколи не отримує сирий CSV і ніколи не рахує сама; вона бачить лише
JSON із готовими фактами. Деталі промптів і міркування за ними — у
[`prompts.md`](prompts.md).

### Безпека згенерованого коду

Код від LLM не виконується як є. Перед запуском `check_code` відхиляє імпорти,
роботу з файлами й мережею, `eval`/`exec` і доступ до dunder-атрибутів, а
виконання йде з урізаним `__builtins__` і на копії датафрейму, тому вихідні
дані змінити неможливо. Промпт і перевірка дублюють одне одного свідомо:
промпт зменшує кількість поганих генерацій, перевірка ловить ті, що прослизнули.

## Тести

```bash
python -m pytest tests -q
```

Тести перевіряють саме ризиковані місця: що верифікатор ловить вигадане число
й не чіпає округлене, що пісочниця відхиляє небезпечний код і не змінює
вихідний датафрейм, і що декомпозиція знаходить обвал iOS у демо-даних.

## Технології

Python 3.11+, pandas, numpy, pytest; `anthropic` / `openai` SDK для доступу до
моделі; стандартний `argparse` для CLI — без зайвих залежностей.
